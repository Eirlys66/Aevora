## 这是什么

Aevora 是一套个人自动化平台，两个领域共用一套底座：

- **工作区**：讨论 → 提案 → 授权 → 作业 → 核实。模型只能提议，不能自己动手；每次执行都对应一次明确授权。
- **日常区**：一套分层记忆（T0 不可变原文 + T1 事实 / T2 心语卡 / T3 自我认知 / T4 核心记忆），带召回、冷却与引用校验。

技术上没什么新鲜的：Python + FastAPI + SQLite（手写 SQL，不用 ORM）、React + TypeScript、Linux 命名空间做执行隔离。有意思的部分都在**约束**上——什么时候允许模型动手、记忆凭什么算数、执行失败怎么收尾。文档写的主要是这些。

## 我打算怎么用这个仓库

**它是稳定版本的退路。**

开发发生在一台服务器上，改炸了得有地方取回。所以这里的提交节奏是「攒到能跑 → 打一个快照」，不是逐日流水；分支历史也不会原样搬过来。

这意味着两件事：一是这里的代码总是滞后于我的实际环境；二是**这里的内容以「能跑起来」为合格线，不以「能给别人用」为合格线**。

**2. 按现状提供（AS IS）。**

不附带任何明示或暗示的担保，包括但不限于适用性、正确性、安全性。用出问题自己担。

**3. 没写完。**

**4. 安全边界比你想的薄。**

服务端鉴权是单一 Bearer token，没有多用户隔离；能访问 API 的人就能读写全部数据。**这套东西适合跑在一台只有你自己的机器上，不适合直接搬到公网。** 想拿去用，鉴权、审计、隔离都得自己补。

**5. 里面没有你的数据，也没有别人的。**

这个仓库只放代码与设计，不包含任何真实对话、记忆内容、密钥或部署凭证。

## 目录

```
index.html                       落地页（开 Pages 时直接看这里）
_build_html.py                   docs 下 md → html 的生成脚本（排版统一用）
docs/
  architecture.html              日常区记忆库架构图（浏览器直接打开）
  01-platform.html               01 平台说明（排好版的页面）
  02-data-model.html             02 数据模型（排好版的页面）
  provenance.html                来源说明与同源度审计（排好版的页面）
  01-骨架说明.md                  上面三页的源文件
  02-数据模型.md
  PROVENANCE.md
```

`docs/*.html` 是 `docs/*.md` 生成出来的，改文档请改 `.md`，然后跑
`python3 docs/_build_html.py`（需要 `pip install markdown`）重新生成，别直接改 HTML。

文档只放骨架与数据模型两份——足够看清这套系统的形状，剩下的部分等代码。
