# 01 · 平台说明

## 日常区增量（2026-10-24）

日常区新增 persona、绑定 persona 的 conversation、幂等 turn、独立原始来源消息、助手回复与会话事件。
聊天首版使用非流式 OpenAI 兼容接口，用户消息先提交，助手只在持久化后返回。模型凭据保存在
服务端权限受限文件中；可选访问令牌保护跨设备 API 请求。记忆流水线、自动召回、心语卡片、主动工具和删除接口仍未接入。

该增量尚未执行数据库迁移或自动化验收；新表由 schema v4 在应用启动时增量创建。

## 进程模型

首版两个进程，共享一个 SQLite 数据库（WAL 模式）：

```
浏览器 ── REST + SSE ── API 进程（uvicorn, 127.0.0.1:8081）
                              │
                              ├── SQLite WAL：项目/任务/消息/提案/授权/作业/事件/产物元数据
                              ├── projects/<项目名>/     项目工作目录（将来执行器的读写区）
                              ├── artifacts/<项目名>/    产物本体（路径由服务端生成）
                              └──（同一份库）
                                   Worker 进程
                                     └── Executor 适配器 → NullExecutor（空实现）
```

为什么不用容器：目标机上没有 Docker，且首版是单机单所有者低并发，
原生进程 + 前台脚本足够；等需要独立扩缩容再谈部署形态。

## 数据库是唯一权威

- 任务阶段、授权、作业状态、队列位置**全部**在数据库里；
- 进程内不保存任何"待执行队列"；
- API 崩溃或 Worker 重启，都不会丢作业、也不会重复执行（幂等键 + 租约）；
- 事件与状态写在**同一个事务**里，不会出现"状态变了事件没记"。

## 关键实现选择

| 选择 | 理由 |
|---|---|
| 手写 SQL，不用 ORM | 骨架阶段 SQL 比 ORM 更直观，审计"到底写了什么"更容易 |
| `isolation_level=None` + 显式 `BEGIN IMMEDIATE` | 事务边界完全可控，避免隐式事务把"读-判断-写"拆开 |
| `events.seq` 用 `AUTOINCREMENT` | 单调且**不复用**已删除序号，客户端游标补读才成立 |
| 路径校验先 `realpath` 再 `commonpath` | 只比对字符串会被 `..` 和符号链接绕过 |
| 每日确认判定在服务端 | 前端弹窗只是外壳，权限来源必须是数据库 |
| 每日确认记在**全局** `daily_acks`（day 主键），不在授权行上 | 授权是任务级对象，确认是系统级状态；混在一起会让同一天多个任务各弹一次 |
| 消息角色由服务端写死（工作区公共接口只写 `user`） | 即使使用 bearer token，客户端也不能伪造 `assistant` 消息绕过每日确认 |
| 产物路径由服务端生成，客户端只给文件名 | 让客户端参与拼路径，等于把目录穿越的入口留在上传接口上 |
| 产物下载强制 `attachment` + `nosniff` | 产物是同源内容，内联渲染 HTML 就是一个存储型 XSS |
| 上传上限在流式写入时按**实际字节**判定 | Content-Length 可以撒谎；写满上限就中断，避免被灌满磁盘 |
| 执行器契约用同步迭代器 | 首版单 Worker 单线程，同步模型更容易推理崩溃点 |
